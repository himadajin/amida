# あみだくじ SPA 仕様書

## 目的

あみだくじを作成し、参加者が結果に到達するまでの経路を1人ずつ確認できるシングルページアプリケーションを作成する。

初版では人数を5人に固定し、入力、生成、経路表示、結果確認までを1画面で完結させる。内部ロジックは将来的に人数や横線数を可変にできるように設計する。

## 技術スタック

- TypeScript
- Vite
- React
- Tailwind CSS
- Vitest
- ESLint
- Prettier

## 設計方針

- 不要な処理や抽象化を避け、なるべく簡潔に実装する。
- あみだくじ生成、経路計算、結果割り当ては、テストしやすい形で UI から分離する。
- テストしやすい構造を優先する。
- 初版では仕様を絞り、後から人数、横線数、表示演出を拡張できる余地を残す。

## 初版スコープ

### 対象機能

- 参加者名を5人分入力できる。
- 結果名を5件分入力できる。
- 初期値として参加者名 `A`、`B`、`C`、`D`、`E` を表示する。
- 初期値として結果名 `1`、`2`、`3`、`4`、`5` を表示する。
- ボタン操作であみだくじを生成できる。
- 生成されたあみだくじを画面に表示できる。
- 参加者を1人ずつ選び、経路をたどる演出を表示できる。
- 経路表示後、その参加者の結果を表示できる。
- 全参加者の結果を最終的に確認できる。
- 同じ縦軸を一直線に進むだけの参加者が出ないようにする。

### 初版では扱わない機能

- 参加者数の UI 上での変更
- 横線数の UI 上での変更
- あみだくじの保存
- 結果の履歴管理
- 画像としてのエクスポート
- 複数ページ構成

## あみだくじ仕様

### 基本仕様

- 初版の縦軸数は5本固定とする。
- 内部的には、将来的に縦軸数を可変にできるようにする。
- 横線は隣接する縦軸同士だけを接続する。
- 横線数は初版では8本固定とする。
- 生成される横線は、上から下へたどれるように配置する。

### 横線の制約

- 横線同士が重なったり、経路として不自然につながったりしないように配置する。
- すべての縦軸は、最低1回は横線に接続される。
  - 左端または右端の縦軸も対象とする。
  - 参加者が一度も横移動せずに結果へ到達する状態を避ける。
- あみだくじの結果は必ず重複しない。
  - 参加者5人は、それぞれ異なる結果に到達する。

### 経路

- 参加者は上から下へ進む。
- 進行中の縦軸に横線がある場合、その横線をたどって隣の縦軸へ移動する。
- 最下部に到達した位置に対応する結果を、その参加者の結果とする。

## アプリケーション状態

アプリケーションは、入力、あみだ生成、経路表示、結果確認の流れを持つ。

- 参加者名と結果名を編集できる状態から開始する。
- 入力内容に問題がなければ、あみだくじを生成できる。
- あみだくじ生成後は、参加者名、結果名、あみだくじを表示する。
- 参加者ごとの経路表示を開始できる。
- 演出中は同時に別の参加者の経路表示を開始しない。
- 経路表示が完了した参加者から、結果を確認できる。
- 全参加者の経路表示が終わったら、最終結果一覧を確認できる。
- 生成後も、同じ入力からあみだくじを作り直せる。
- 入力内容を編集し直せる。

## UI 仕様

### 全体

- シングルページで完結する。
- ライトモードのみ対応する。
- Tailwind CSS のデフォルトカラーパレットを使用する。
- モダンでシンプルな見た目にする。
- 装飾よりも、入力、生成、経路確認の分かりやすさを優先する。

### 画面構成

- ヘッダー
  - アプリ名を表示する。
  - 短い説明文を表示する。
- 入力エリア
  - 参加者名5件の入力欄を表示する。
  - 結果名5件の入力欄を表示する。
- 操作エリア
  - 「あみだを作る」ボタンを表示する。
  - 生成後は「もう一度作る」ボタンを表示する。
  - 生成後は「入力を編集する」ボタンを表示する。
- あみだ表示エリア
  - 上部に参加者名を表示する。
  - 中央にあみだくじを表示する。
  - 下部に結果名を表示する。
- 結果エリア
  - 経路表示済みの参加者と結果の対応を表示する。
  - 全員分の表示が終わったら、最終結果一覧として表示する。

### あみだ表示

- 縦線、横線、選択中の経路が分かるように表示する。
- 選択中の経路は通常線より目立つ色と太さで表示する。
- 経路表示済みの参加者は、結果が分かる状態にする。
- まだ経路表示していない参加者の結果は隠す。

### 経路表示操作

- あみだ生成後、参加者ごとに「たどる」操作を行える。
- 参加者を1人選ぶと、その参加者の経路が上から下へ順に表示される。
- 経路表示が完了するまで、その参加者の結果は表示しない。
- 経路表示が完了したら、対応する結果を表示する。
- すでに結果表示済みの参加者は再度たどれるが、結果は変わらない。

## バリデーション

- 参加者名が空の場合はエラーを表示する。
- 結果名が空の場合はエラーを表示する。
- 参加者名の重複は初版では許可する。
- 結果名の重複は初版では許可する。
- エラーがある場合は、あみだくじを生成できない。

## テスト方針

### ロジックテスト

- 指定した人数と横線数であみだくじを生成できる。
- 横線が隣接する縦軸同士だけを接続する。
- 横線同士が不自然に重ならない。
- すべての縦軸が最低1回は横線に接続される。
- 参加者が正しい経路をたどり、対応する結果に到達する。
- 結果の対応に重複がない。
- 経路表示に必要な情報を検証できる。
- 生成結果を決定的に扱えるようにし、再現性のあるテストを書ける。

### UI テスト

- 初期表示で参加者名と結果名の初期値が表示される。
- 空欄がある場合、あみだくじを生成できない。
- 「あみだを作る」であみだくじが表示される。
- 参加者を選ぶと経路表示が開始される。
- 経路表示完了後に結果が表示される。
- 全員分の経路表示後、最終結果一覧が表示される。
